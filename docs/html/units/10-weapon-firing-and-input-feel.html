从输入采样到可预测的网络射击循环

系统把目标点计算、实际枪口方向、本地表现、服务器授权和射速循环拆成独立阶段，使输入反馈不必等待网络往返，同时保留服务器统一分发射击事件的能力。

01

准心选点：只由本地玩家构造 HitTarget

CombatComponent 只为 IsLocallyControlled() 的角色执行准心检测。系统取得视口中心，通过 DeprojectScreenToWorld 得到世界起点与方向；远端角色不在每台机器上重复计算同一条准心射线。

避开自身模型第三人称摄像机位于角色身后，射线起点沿准心方向前移 DistanceToCharacter + 100.f，减少首先命中自己角色的概率。
始终有效的目标存在阻挡时使用 ImpactPoint；没有阻挡时将射程终点写入 ImpactPoint，因此天空和远处空白区域同样能得到稳定 HitTarget。
Screen Center→DeprojectScreenToWorld→Start + Direction × TRACE_LENGTH
02

枪口方向：摄像机决定目标，MuzzleFlash 决定发射角

准心射线先回答玩家希望命中的世界位置，武器再从 MuzzleFlash Socket 指向 HitTarget，通过 (HitTarget - MuzzleLocation).Rotation() 得到实际射击角度。这样既保留第三人称准心体验，也确保弹体从枪口而不是摄像机生成。

视差处理摄像机与枪口不共点；先求世界目标、再由枪口重新定向，避免直接复用摄像机方向造成近距离偏移。
散布复用bUseScatter 以原始目标方向建立散布球，在球内采样随机点，再从枪口指向该点；输入采样方式不因武器类型改变。
类型分派Projectile、HitScan 与 Shotgun 共享状态、射速和网络入口，只在最终传入单个 HitTarget 或一组散布目标时分化。
03

本地预测：即时表现与服务器多播互不重复

通过 CanFire 后，开火客户端立即调用 LocalFire，同步播放角色 Montage、武器动画、弹壳、准心扩散脉冲并预测扣除弹药；同一输入同时调用 ServerFire，由服务器校验射速参数和战斗状态后执行 MulticastFire。

Input→LocalFire + ServerFire→MulticastFire→Remote LocalFire
多播去重最初开火的普通客户端已执行预测；收到 Multicast 时通过 IsLocallyControlled 且非 Authority 的条件提前返回，避免动画、弹壳和扣弹执行两次。
弹药校正预测值用于立即刷新 HUD；服务器随后复制权威 Ammo，客户端通过 OnRep_Ammo 使用绝对值完成最终校正。
观察者一致性服务器与其他客户端仍执行多播表现，因此所有观察者都能看到同一次射击，而输入端不承担网络往返造成的操作延迟。
04

连续开火：射速门控与跨状态输入意图

每次成功射击立即令 bCanFire = false，并以 Weapon::FireDelay 启动计时器。FireTimerFinished 恢复门控后，只有按键仍被保持、武器允许 Automatic 且 CombatState 可开火时才进入下一轮，射速因此不依赖帧率或输入事件频率。

持续输入bFireButtonPressed 保存“继续射击”的意图，而不是只记录一次按键事件；松开按键后，下一次 Timer 结束不会续射。
换弹后衔接FinishReloading 与 OnRep_CombatState 都会在回到 Unoccupied 后重试 Fire；若一条路径先成功，bCanFire 会阻止另一条重复触发。
空弹匣换弹最后一发完成自身 FireDelay 后再检查空弹匣并请求 Reload，保证该发的动画和射击节奏完整结束。
